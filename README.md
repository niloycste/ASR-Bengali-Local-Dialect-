## ✨ Overview

**AncholVox** is a challenging silver-standard research benchmark for **Bangladeshi regional dialect Automatic Speech Recognition** with **Bengali–English code-switching detected in automatic transcripts**.

Unlike existing Bengali ASR datasets that focus on either standard Bengali, dialects, or limited code-switching, AncholVox targets their intersection in a selected sample of online speech:

> “chatgaiya bhashay phone unboxing kortachi, honestly speaking camera performance onek bhalo”

The collection covers **15 regional labels** and **41,499 transcribed clips** (about **131.2 hours**) of online speech, retained from 52,020 segmented clips through automatic filtering.

> ⚠️ **Important label note**  
> AncholVox uses **silver-standard labels** generated by Whisper large-v3 and refined through an LLM-based quality pipeline. WER and CER therefore measure agreement with noisy silver references, not definitive transcription accuracy. The 100-clip, two-annotator study is a limited validation sample, not a conclusive model-ranking experiment.

> **Audit status:** the archived test set is not source-disjoint from the rest of
> the retained corpus: 69 of its 101 inferred source IDs cross the boundary,
> and 3,772 of 4,088 test clips carry one of those IDs. Missing historical
> train/dev manifests prevent a claim that every overlapping source entered
> training. Existing fine-tuned scores are historical diagnostics, not
> leakage-free generalization estimates. A future partition is now frozen and
> passes both source-ID and exact-audio checks, but all systems still need retraining.
> A SHA-256 audit also found 782 exact-audio duplicate groups, 326 of which
> cross the historical test boundary.

## 🔍 Why AncholVox?

Existing Bengali ASR resources usually cover **either dialectal speech or code-switching**, but not both together.

| Dataset | Dialectal Speech | Code-Switching | Hours |
|---|:---:|:---:|---:|
| OpenSLR-37 | No | No | ~229 |
| MUCS 2021 Bengali–English | Not established | Yes | 46.11 train + 7.02 test |
| Ben-10 (2025) | ✅ 10 dialects | ❌ | 78 |
| **AncholVox** | ✅ **15 regional labels** | ✅ **Bengali + English** | **~131** |

AncholVox addresses this gap using selected online speech whose silver transcripts contain:

- regional Bangladeshi dialects,
- standard Bengali forms,
- English words and phrases,
- informal spoken-language spelling variation,
- noisy real-world audio.

## 🏆 Benchmark Results

All archived models were evaluated on a nominal test set of **4,088 clips**.
An artifact audit found that this historical set is **not source-isolated**;
fine-tuned scores below are retained for diagnosis only.

**WER retains all repetitions. WER-RC applies explicit repetition-collapse
post-processing. Lower is better; higher CS-F1 is better.**

| Model | WER ↓ | WER-RC ↓ | CER ↓ | WER-CS ↓ | CS-F1 ↑ |
|---|---:|---:|---:|---:|---:|
| Whisper-small zero-shot | 1.142 | 1.065 | 1.031 | 1.133 | 0.000 |
| Whisper large-v3 zero-shot | 0.930 | 0.910 | 0.757 | **0.818** | 0.144 |
| MMS-1B zero-shot | 0.989 | 0.989 | 0.571 | 0.940 | 0.041 |
| wav2vec2-XLS-R-BN zero-shot | 0.963 | 0.963 | 0.622 | 0.935 | 0.044 |
| **wav2vec2 fine-tuned CTC** | **0.861** | 0.860 | **0.493** | 0.877 | 0.135 |
| Whisper FT BN-only | 0.923 | **0.800** | 0.575 | 0.933 | 0.011 |
| Whisper FT CS-only | 1.065 | 0.883 | 0.679 | 0.963 | **0.276** |
| **Whisper FT ALL (joint data)** | 0.964 | 0.801 | 0.597 | 0.959 | 0.192 |

### 📊 Main Findings

- Historical joint-data Whisper scores **0.964**, versus **1.142** for zero-shot Whisper-small; source leakage prevents a fine-tuning generalization claim.
- Fine-tuned wav2vec2 has the lowest historical primary silver-reference WER (**0.861**).
- Repetition collapse is reported separately: Whisper ALL changes from **0.964 WER to 0.801 WER-RC**.
- Under WER-RC, Whisper ALL and BN-only are close; these are practical training recipes, not controlled data-composition ablations.
- Joint-data Whisper has higher transcript-label CS-F1 than BN-only (**0.192 vs. 0.011**), while CS-only is highest (**0.276**); labels are automatic and transcript-derived.
- On the 100-clip human-reference evaluation, MMS-1B has the lowest WER against both annotators.

> 💡 **Why are WER values high?**  
> This task is intentionally difficult: 15 low-resource dialects, real-world audio, code-switching, spelling variation, and silver-standard labels. Since dialectal Bengali has no standardized spelling, **CER is often more informative than WER** for this benchmark.

### Phase 1 — Build the Dataset

```bash
cd dataset_pipeline

python 01_download_audio.py
python 01b_download_extra_urls.py
python convert_webm.py

python 02_segment_audio.py
python 03_auto_transcribe.py

python 04a_retag_borrowed_english.py
python 04b_auto_annotate.py
python 04c_llm_transcript_judge.py

python ..\evaluation\20_dataset_audit.py --hash-audio
python ..\evaluation\21_verify_repaired_split.py --freeze
python augment_data.py --all --seed 42
python 05_build_dataset.py
```

The first command writes a complete SHA-256 manifest for all retained originals.
The digest covers the complete WAV file byte stream, so it detects byte-identical
files but not equivalent decoded audio stored with different encoding or metadata.
The verifier then joins source IDs connected by any byte-identical duplicate,
splits those transitive components, checks both kinds of overlap, and freezes
29,224/3,855/3,297 quality-filtered original clip IDs. Augmentation refuses to
run without that frozen training list and replaces any older augmented rows, so
dev/test originals cannot be augmented into training.

The future-release filter is transcript-only: it rejects empty stripped text,
any U+FFFD replacement character, or any alphabetic character outside ASCII and
Bengali U+0980-U+09FF. Of 41,499 originals, 5,027 match U+FFFD and 453 match the
foreign-alphabet rule; 357 match both, so 5,123 are excluded. The remaining
36,376 originals total 113.61 hours and include 1,837 transcript-labelled CS
clips. Exact overlap-aware counts and per-label split hours/CS coverage are in
`evaluation/results/repaired_split_verification.json` and
`evaluation/results/repaired_split_profile.csv`.

`augment_data.py --all` was also the augmentation condition recorded for the
historical 60,936-clip training pool. Its exact train/dev manifests are absent,
so that historical count is not a reproducible frozen experimental snapshot and
must not be confused with the partition above.

#### Archiving the exact split

A fixed seed does not by itself pin a split. The assignment also depends on the
input snapshot and integrity relations. `21_verify_repaired_split.py --freeze`
writes immutable original-clip lists plus per-split, combined, and audio-hash
checksums under `dataset_pipeline/repaired_split_manifests/`; it refuses to
overwrite a different assignment. After augmentation and materialization, the
release manifests can additionally be exported with:

```bash
python 08_export_split_manifests.py
```

This writes `dataset_pipeline/split_manifests/` with per-split clip-ID lists,
manifests, and `SPLIT_CHECKSUMS.json` (SHA-256 of each split's sorted clip IDs).
The historical test set is archived in `evaluation/results/test_set.json`:
4,088 clips, 176 transcript-labelled code-switched clips, and 13.2 hours.
The audit shows that 69 of its 101 inferred sources also occur outside that
manifest. The frozen future manifests have a new identity and require model
retraining; they are not the original experimental snapshot.

### Annotation Pipeline

| Condition | Action |
|---|---|
| `no_speech_prob < 0.30` | Auto-accept transcript |
| `0.30 ≤ no_speech_prob < 0.60` | Qwen2.5 LLM judge reviews transcript |
| `no_speech_prob ≥ 0.60` | Reject clip |

The fixed construction model is `qwen2.5:14b` with temperature 0 and seed 42.
The parser derives the result from four binary criteria: 3--4 YES responses are
accepted, exactly 2 are uncertain, and 0--1 are rejected. It also saves the
per-criterion values instead of trusting the model's overall label.

The text-only LLM judge evaluates its configured textual criteria:

- Bengali validity,
- code-switch plausibility,
- dialect-form plausibility,
- speech/noise and hallucination risk.

The stored pipeline manifests show the practical effect of this cascade:
39,772 high-confidence clips are accepted automatically; 1,727 of 8,712
borderline clips (19.8%) are accepted by the judge, giving 41,499 released
clips. The judge is text-only and cannot verify alignment with audio.
The archived final snapshot stores overall Qwen votes but not all four
criterion values. The current script records them and resolves decisions
deterministically; any regenerated snapshot should therefore receive a new
version identifier.

> The 3-model LLM ensemble is used only for evaluation, not dataset construction.

Run the human-reference evaluation (scores every model against the two
independent 100-clip human transcripts, under the same primary scoring
condition as the silver benchmark):

```bash
python 14_human_test_wer.py
python 15_inter_annotator_agreement.py
```

Run the LLM-ensemble evaluation. All ASR models are judged on **one shared,
seeded, stratified 50-clip sample** (25 code-switched / 25 Bengali-only, spread
across dialects), so the per-model scores are paired and comparable. The clip
list and its SHA-256 are written to
`results/llm_judge/judge_sample.json`; omit `--model` to judge every system:

On CPU-only Ollama a 12B judge takes roughly a minute per clip, so judge one
ASR model per invocation (each model's results are saved when it finishes), then
run `--summarize` once to build the cross-model comparison and the paired
significance tests:

```bash
python 11_llm_judge.py --model whisper_large_v3
python 11_llm_judge.py --model ft_whisper_all
python 11_llm_judge.py --model ft_whisper_bn_only
python 11_llm_judge.py --model ft_whisper_cs_only
python 11_llm_judge.py --summarize
```

All evaluation outputs are written to:

```text
evaluation/results/
```

Two evaluation conditions are produced for every system:

- **Primary WER/CER:** agreement with the silver references after Unicode,
  case, punctuation, and whitespace normalization;
  all repeated characters and words are retained, and loanword spelling variants
  are **not** merged. This is `primary_normalize()` in
  `dataset_pipeline/text_normalization.py`, and it is the single function used
  for the silver-reference benchmark, the human-reference evaluation
  (`14_human_test_wer.py`), and the inter-annotator numbers
  (`15_inter_annotator_agreement.py`), so all three are directly comparable.
- **WER-RC/CER-RC:** the same normalization plus explicit degenerate-repetition
  collapse as system post-processing.

`full_normalize()` also exists and additionally maps pronunciation variants and
collapses repetitions. It is strictly more lenient and is **not** used for any
reported number; do not use it to score a result that goes into the paper.

Metric scopes differ and are not interchangeable:

- `wer_overall`, `wer_overall_repetition_collapsed`, `cer_overall` — all 4,088
  test clips.
- `wer_bn_words_cs` (**WER-BN-CS**), `wer_en_words_cs` (**WER-EN-CS**),
  `lb_wer`, and `wer_cs_subset` — the 176 code-switched clips only. The first
  two mean Bengali- and English-script words *within mixed clips*, not
  Bengali-only or English-only clips. `lb_wer` is exactly their mean because
  they share one scope.
- `wer_bn_words_corpus`, `wer_en_words_corpus` — corpus-wide per-script WER,
  reported for reference; **not** the components of `lb_wer`.
- `cs_detection.cs_f1` — clip-level binary classification over all 4,088 clips
  (176 positives, 3,912 negatives), not a CS-subset metric.

`06_statistical_analysis.py` recomputes both conditions using a two-sided paired
bootstrap with 10,000 resamples, 95% percentile intervals, a fixed seed, and a
plus-one Monte Carlo correction. It reports both clip-level results and
exploratory source-video-cluster results. Source clustering is preferred for
within-test uncertainty, but it does not prove speaker independence or repair
historical train–test source overlap. It also reports bootstrap intervals for
WER-CS, CS-F1, English-word survival, and paired CS-F1 differences. For example,
Whisper ALL has CS-F1 0.192 (95% CI [0.120, 0.264]); ALL minus BN-only is
+0.181 ([0.111, 0.253]), while ALL minus CS-only is -0.083
([-0.153, -0.015]).

## 📏 Metrics

| Metric | Meaning |
|---|---|
| **WER** | Word Error Rate |
| **CER** | Character Error Rate; primary metric because it is more robust to spelling variation |
| **WER-BN-CS** | WER for Bengali-script reference words within code-switched clips |
| **WER-EN-CS** | WER for English-script reference words within code-switched clips |
| **WER-BN-only** | Whole-clip WER on Bengali-only clips; distinct from WER-BN-CS |
| **LB-WER** | Equal-weight mean of Bengali-script and English-script WER on CS clips |
| **WER-CS** | WER on code-switched clips only |
| **CS-F1** | F1 for detecting whether a hypothesis contains code-switching |
| **EN-Survival** | Fraction of English reference words preserved on code-switched clips |
| **Bootstrap CI** | Paired bootstrap confidence interval |
| **p-value** | Two-sided paired bootstrap significance test |
| **Cohen’s d** | Effect size based on corpus WER resampling |

## 🧠 Key Design Decisions

### 1. Dialect-name queries instead of region-name queries

Region-name queries such as “Chittagong vlog” often return speakers from a region using standard Bengali for a general audience. Dialect-name queries are more likely to surface creators who deliberately speak in the dialect.

### 2. Content genres likely to contain code-switching

Search queries target content where English terms commonly appear in informal
speech. Switching labels are still derived from the silver transcripts:

- street interviews,
- reaction videos,
- technology and phone reviews,
- campus and career discussions,
- gaming and livestreams,
- personal vlogs.

### 3. Silver-standard transcription

Whisper large-v3 is used as a best-effort multilingual transcriber. The
script-based detector reliably distinguishes Bengali and Latin characters in
the generated text, but it does **not** independently establish which languages
were spoken in the audio.

A human-validation subset is included to estimate label quality and benchmark reliability.

It contains only 100 clips and two independent, non-adjudicated references, so
it is a limited validation study rather than definitive evidence of model rankings.

> Caveat: Since labels are generated by Whisper large-v3, the reference can be
> model-family dependent. The provenance audit found 0.9271 WER when archived
> construction-time large-v3 transcripts are treated as references for the
> paired evaluation-time outputs, and 0.9298 WER when those evaluation outputs
> are compared with the stored silver references. Missing historical revisions
> and settings prevent a unique retrospective diagnosis. See
> [`REFERENCE_PIPELINE_PROVENANCE.md`](REFERENCE_PIPELINE_PROVENANCE.md).

### 4. Why evaluate joint-data Whisper

Whisper has a multilingual subword vocabulary that can represent both Bengali and Latin-script tokens in a single decoding pass. This makes it better suited to mixed-script code-switching than monolingual CTC systems.

It is not presented as universally best: fine-tuned wav2vec2 has the lowest
primary silver-reference WER, while MMS-1B has the lowest WER on the current
human-reference subset. Joint-data Whisper is retained because it provides a
useful balance of mixed-script generation and repetition-controlled system
performance.

## ✅ Recommended Use

AncholVox can be used for:

- dialectal Bengali ASR,
- Bengali–English code-switching research,
- robust speech recognition under noisy real-world conditions,
- cross-dialect ASR evaluation,
- mixed-script recognition metrics,
- silver-label benchmarking studies.

## ⚠️ Limitations

- Labels are silver-standard, not fully human-transcribed.
- Dialect spelling is not standardized.
- WER may over-penalize valid spelling variation.
- Online-source distribution is not demographically balanced.
- No consented demographic labels are available, so subgroup-fairness claims
  cannot be made.
- Whisper-generated labels may introduce model-family bias.
- Code-switching is detected from the automatic transcript in 5.69% of retained
  clips and 176 historical test clips; this is not a population frequency or an
  audio-verified spoken-language label.
- The construction judge sees text rather than audio, and its decisions are
  heuristic rather than human-verified acoustic-quality labels.
- No Ben-10, Common Voice, or other external-corpus evaluation is reported, so
  the current results do not establish out-of-domain generalization.
- The archived test set crosses source boundaries with the retained remainder;
  all fine-tuned systems require retraining on the repaired split. The frozen
  repaired ID lists contain 29,224/3,855/3,297 original train/dev/test clips
  after text-quality filtering, with zero inferred-source and exact-audio
  overlap; complete manifests, augmentation, predictions, and metrics must be
  regenerated before reporting repaired-split model results.
- Exact-audio hashing found 326 duplicate groups crossing the historical test
  boundary. Near-duplicate acoustic fingerprinting remains pending.
- Creator/speaker overlap and near-duplicate audio have not been established;
  source IDs do not prove speaker separation.
- Clip-level bootstrap intervals can be too narrow when clips share a source;
  source-cluster results still do not resolve speaker dependence or split leakage.
- Repetition collapse is nonstandard system post-processing and is therefore
  reported separately from primary WER.
- Public accessibility does not itself authorize audio redistribution; final
  release contents depend on documented institutional and rights review.
